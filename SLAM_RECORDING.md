# Live SLAM recording

Use one Ubuntu Terminal window. The fleet launch opens Gazebo, RViz, live SLAM,
and the dashboard together:

```bash
cd ~/amr_ws
bash run_swarmx_v2_large.sh enabled:=false use_rviz:=true max_linear_speed:=3.80 max_angular_speed:=7.50
```

These speed values are requested controller and Gazebo caps in m/s and rad/s.
Measured physical speed can be lower because acceleration, steering, and
obstacle safety controls remain active. This speed combination has not passed
a physical stability gate; use `max_linear_speed:=0.60 max_angular_speed:=0.50`
for the previously checked conservative profile.

For a fresh checkout, first source `/opt/ros/lyrical/setup.bash` and build with
`colcon build --symlink-install --packages-select amr_simulation edge_ai_nav`.

Open http://localhost:8091/fleet. Keep Gazebo and the RViz window whose filename
ends in `swarmx_v2_slam.rviz` visible. Assign a normal task manually to ALPHA 1
using the dashboard. As ALPHA 1 moves, show the map growing and red upper LiDAR
returns plus yellow low LiDAR returns from short obstacles
on shelves, walls, and physical obstacles. A complete warehouse map requires
exploration; gray space is unknown, white is free, and black is occupied.

The map is generated by SLAM Toolbox from the real simulated `/alpha_1/scan`
and odometry TF. It is not the dashboard's predefined warehouse drawing.
Red returns update live; map updates are slower and depend on accepted scans.
This demonstrates LiDAR obstacle detection and SLAM mapping, not semantic
object classification. Robot avoidance remains the existing local controller.

The fleet observer already names its world-odometry frame `map`. SLAM uses it
as odometry and publishes `slam_map -> map`, preserving the fleet transforms.
`/map` is the live OccupancyGrid in `slam_map`. Stop the launch terminal with
Ctrl+C when recording is finished.
